Methodology

Soft-filter criteria (GATK VariantFiltration)

The joint-calling VCF is soft-filtered via GATK4 VariantFiltration as a fallback when VQSR cannot run (no known-sites for custom genomes). This populates the FILTER column but retains all variants. Filters use vc.isSNP() / vc.isIndel() JEXL syntax.

Universal filters (SNPs + INDELs)

Filter nameExpression
QD_filterQD < 2.0
QUAL_filterQUAL < 30.0

SNP-only filters (GATK best practices)

Filter nameExpression
FS_filtervc.isSNP() && FS > 60.0
SOR_filtervc.isSNP() && SOR > 3.0
MQ_filtervc.isSNP() && MQ < 40.0
MQRankSum_filtervc.isSNP() && MQRankSum < −12.5
ReadPosRankSum_filtervc.isSNP() && ReadPosRankSum < −8.0

INDEL-only filters (more lenient per GATK recommendation)

Filter nameExpression
FS_INDEL_filtervc.isIndel() && FS > 200.0
ReadPosRankSum_INDEL_filtervc.isIndel() && ReadPosRankSum < −20.0

No SOR, MQ, or MQRankSum filters for INDELs per GATK recommendation.

Filtering pipeline

Joint VCF → soft-filter (GATK VariantFiltration) → split per sample → SnpEff annotation

StepSource VCFDescription
1. Soft-filtered *_soft_filtered.vcf.gz Joint VCF with FILTER column populated (PASS or quality flags) — no variants removed
2. Split per sample *.from_joint_calling.vcf.gz Individual sample VCFs extracted via bcftools view -s, ref-only genotypes removed
3. Annotated *_snpEff.ann.vcf.gz SnpEff functional annotation (gene, impact, protein change)

What the HaplotypeCaller column shows

The HaplotypeCaller count in the Sample Overview table is the total number of non-reference variants per sample after soft filtering and SnpEff annotation (step 3 above). This includes all variants regardless of FILTER status (PASS and flagged). Use the per-sample IGV reports or the cohort report's VCF_FILTER column to distinguish PASS variants from those flagged by soft filters.

Optional: hard filtering for downstream analysis

The reports and downloadable VCFs intentionally include all soft-filtered variants so users can inspect flagged calls in IGV before deciding on thresholds. For downstream analysis requiring a high-confidence call set, consider applying additional hard filters on the exported VCF, for example: 

bcftools view -f PASS input.vcf.gz \
  | bcftools filter -i 'FORMAT/GQ>=20 && FORMAT/DP>=8' \
  | bcftools filter -i 'FORMAT/VAF>=0.90'   # clonal samples
  # or FORMAT/VAF>=0.05 for population samples

Adjust thresholds based on your experiment design (ploidy, clonal vs. population, expected allele frequency). The pipeline produces hard-filtered VCFs as an intermediate output (*.hard_filtered_snpEff.ann.vcf.gz) with default thresholds PASS + GQ≥20 + DP≥8 + AF≥0.80 (clonal) / ≥0.05 (population), available in the annotation output directory for reference.

Notes

  • The cohort card shows unique variant sites in the joint VCF (one row per site), so it is lower than the sum of per-sample counts.
  • The cohort IGV report may show more rows than the card number because bcftools norm -m- splits multi-allelic sites into separate records.
  • All reports include all non-reference variants (soft-filtered only) — use the VCF_FILTER column to identify PASS variants.
SV event matrix (Manta + TIDDIT)

SVs detected independently by Manta and TIDDIT, merged into a cohort matrix by build_sv_matrix.py. Per-sample columns show caller(s): Manta, TIDDIT, or Manta+TIDDIT.

Why counts differ

  • SV Events card + matrix: PASS-filtered, deduplicated across callers (sv_cohort_matrix_union_pass.csv)
  • Sample Overview TIDDIT/Manta columns: raw unfiltered per-sample VCF counts from bcftools stats

Per-sample counts are much higher because they include non-PASS calls and are not deduplicated. TIDDIT in particular generates many low-confidence calls.

Copy number analysis (CNVKit)

Copy number is called by CNVKit using a flat reference (no matched normal pooling).

Card counts

Cards show changed / total regions. A region counts as changed when any sample's log2 ratio is < −0.4 (loss) or > 0.3 (gain) — same thresholds as heatmap coloring.

Display values

Default: absolute CN = ploidy × 2log2. Toggle to log2 ratio (raw segmented depth vs. flat reference). Colors always track log2: 0 = neutral, negative = loss (red), positive = gain (blue), ≥2.3 = high amplification (dark blue).

IGV report generation

Per-sample and cohort reports are generated with igv-reports. Processing steps:

  1. Multi-allelic split — bcftools norm -m- so each alt allele has its own row
  2. FILTER promotion — FILTER column copied to INFO/VCF_FILTER (igv-reports only reads INFO)
  3. VAF annotation — bcftools +fill-tags -- -t FORMAT/VAF
  4. Report creation — create_report with ±500 bp flanking, CRAM tracks, GFF3 gene annotations
  5. VCF downloads — pre-normalization annotated VCFs published to vcf/ folder, organized by variant caller; reports link to these files for download

The cohort report uses the soft-filtered joint VCF (all variants, FILTER column visible). Per-sample reports use the annotated individual VCFs from joint calling. Both include all non-reference variants so users can inspect flagged variants in IGV.

VCF Downloads: The vcf/ folder contains pre-normalization annotated VCFs suitable for sharing and downstream analysis, organized by variant caller (haplotypecaller/, cnvkit/, manta/). These are the canonical variant calls before multi-allelic splitting. See vcf/README.md for details and reproducibility instructions.
