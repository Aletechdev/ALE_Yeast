# Frozen v1 baseline — do not regenerate

This directory was generated by `generate_demo_reports.nf` (the old inline-process pipeline)
with manually pre-populated `data/` files. It uses legacy filenames:

- `cn_chr_summary_stringent.csv` (now `cn_chr_summary_germline.csv`)
- `cn_cohort_matrix.csv` (now `cn_cohort_full.csv`)

`generate_index.py` has since been updated to expect the new names, so re-running
`generate_ottilie_reports.sh` will produce an `index.html` missing the aneuploidy section.

## Current state

- **`ottilie_4samples/`** — frozen v1 baseline (this directory). Do not regenerate.
- **`ottilie_4samples_v2/`** — generated by `generate_ottilie_reports_v2.sh` using the
  MUTATION_REPORT subworkflow, which auto-generates all CN/SV data files.
- **`generate_ottilie_reports.sh`** — still points to v1 pipeline (`generate_demo_reports.nf`).
  Not updated to v2 because both scripts are being superseded by the main pipeline
  integration (`bin/test_ottilie.sh` with `--generate_reports`).

## Migration path

Both `generate_ottilie_reports.sh` and `generate_ottilie_reports_v2.sh` are standalone
launchers for report generation. The long-term target is `--generate_reports` in the
main Sarek pipeline (`bin/test_ottilie.sh`), which runs the MUTATION_REPORT subworkflow
as part of the full pipeline. Once that is validated, these standalone scripts and
`generate_demo_reports.nf` can be removed.
