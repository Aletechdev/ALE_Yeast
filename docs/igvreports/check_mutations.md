# IGVReports Architecture for ALE Variant Review

## Architecture: Index Page + Per-Sample Reports with Cross-Linking

```
demo/
├── index.html                    # Navigation hub (generated by Nextflow)
├── cohort_report.html            # All variants, 7:3 table/IGV split
└── samples/
    ├── A0-F0-I1-R1_report.html   # Per-sample: ~130 variants + CRAM pileups (1:1 split)
    ├── A1-F6-I1-R1_report.html
    └── ...
```

**Navigation paths**:
- **index.html** → cohort report or any per-sample report
- **Cohort table** → click a sample's GT/AD/VAF cell → opens that sample's report at the exact variant position (see "Cross-Linking" section below)
- Per-sample reports are self-contained with embedded alignment data

## Performance Optimization for HTML Load Time

### Problem
The no-tracks cohort report (8.9 MB, 1,748 variants × 17 samples) can be slow to load in browser due to:
- Large DOM: 1,748 rows × ~170 columns (17 samples × 10 fields each)
- All data embedded inline in the HTML
- Default template renders all rows at once (no virtual scrolling)

### Solutions (ordered by impact)

#### 1. Upgrade to igv-reports >= 1.15.0 for Tabulator template (HIGH IMPACT)
The `--tabulator` template uses [Tabulator.js](http://tabulator.info/) with **virtual scrolling** — only visible rows are rendered in the DOM. This is the single biggest improvement for browser load time with many variants. It also adds **per-column filtering** in the table header (dropdown, substring search, numeric range).

**Generation command** (from [igv-reports run_examples.sh](https://github.com/igvteam/igv-reports/blob/master/run_examples.sh)):
```bash
create_report input.vcf.gz --fasta ref.fa \
    --tabulator \
    --filter-config filter_config.yaml \
    --info-columns ANN VCF_FILTER AC AF DP QD MQ \
    --sample-columns GT AD DP GQ VAF \
    --flanking 500 \
    --output cohort_report.html
```

**`--filter-config` YAML format** — defines per-column filter behavior:
```yaml
columns:
  GENE:
    type: string
    filter: contains        # substring search box
  IMPACT:
    type: string
    filter: list            # dropdown with all unique values
  VCF_FILTER:
    type: string
    filter: list            # dropdown: PASS, QD_filter, MQ_filter, etc.
  AF:
    type: number
    filter: range           # min/max numeric slider
  DP:
    type: number
    filter: threshold       # numeric cutoff (e.g., DP >= 10)
    threshold: 10
```

Supported filter types: `contains` (substring), `list` (dropdown), `exact` (precise match), `range` (min/max), `threshold` (numeric cutoff).

**Status**: nf-core module ships v1.12.0; need to override container to >= 1.15.0
**Reference**: [Tabulator example](https://igvteam.github.io/igv-reports/examples/example_vcf_tabulator.html) | [filter_config.yaml](https://github.com/igvteam/igv-reports/blob/master/test/data/variants/filter_config.yaml)

#### 2. Pre-filter to PASS-only variants (HIGH IMPACT)
Reduces 1,748 → ~737 variants (58% reduction), roughly halving HTML size and DOM nodes.

```bash
bcftools view -f PASS joint_calling.vcf.gz -Oz -o pass_only.vcf.gz
bcftools index -t pass_only.vcf.gz
```

#### 3. Per-sample architecture instead of all-in-one (HIGH IMPACT)
Split into: cohort table (lightweight, no per-sample columns) + individual sample reports (with CRAMs, ~100 variants each).

| Report Type | Variants | Samples | Size | Load Time |
|-------------|----------|---------|------|-----------|
| Cohort table (all) | 1,748 | 17 | 8.9 MB | Slow |
| Cohort table (PASS) | ~737 | 17 | ~4 MB | Moderate |
| Per-sample report | ~100 | 1 | 11 MB | Fast |

#### 4. Reduce embedded data per variant (MODERATE IMPACT)
- **`--flanking 200`** instead of 500 — less reference sequence per variant
- **Trim INFO columns** — remove `AN` (constant), `AC` (redundant with GT)
- **Limit `--sample-columns`** — e.g., just `GT VAF` for cohort overview

#### 5. `--no-embed` for server deployment (MODERATE IMPACT)
Available in v1.16.0. References external FASTA/tracks via URLs instead of embedding.
Requires serving from a web server (not a standalone file).

```bash
create_report input.vcf.gz --fasta ref.fa --no-embed --tracks aligned.cram
```

#### 6. Increase variant table height (QUICK FIX)
The default template limits the variant table to 350px (`max-height: 350px` in the collapsible CSS). Post-process the generated HTML to increase it:

```bash
sed -i 's/max-height: 350px;/max-height: 800px;/' cohort_report.html
```

No `create_report` CLI option exists for this. The `--tabulator` template (v1.15.0+) may handle this better with virtual scrolling.

#### 7. Split by chromosome (LOW IMPACT for yeast)
Generate one report per chromosome. More useful for large genomes.
For yeast with 52 contigs and ~1,748 variants total, not worth the complexity.

## Per-Sample VAF (Variant Allele Frequency)

### Problem
HaplotypeCaller outputs `FORMAT/AD` (allelic depths) but not allele frequency.

### Solution: `bcftools +fill-tags -- -t FORMAT/VAF`
Adds `VAF = AD[alt] / (AD[ref] + AD[alt])` as a new FORMAT field.

```bash
bcftools +fill-tags input.vcf.gz -Oz -o with_vaf.vcf.gz -- -t FORMAT/VAF
bcftools index -t with_vaf.vcf.gz
# Then use --sample-columns GT AD DP GQ VAF
```

**Note**: The tag is `FORMAT/VAF` (not `FORMAT/AF`). INFO/AF remains unchanged — it represents population-level allele frequency from joint calling, not per-sample fraction.

| Field | Level | Source | Example | Meaning |
|-------|-------|--------|---------|---------|
| INFO/AF | Cohort | Joint calling | 0.047 | Alt allele frequency across all 17 samples |
| FORMAT/VAF | Sample | bcftools fill-tags | 0.667 | This sample's alt read fraction: AD[alt]/sum(AD) |

## Multi-Allelic Variants and Splitting

### Problem
Joint calling with HaplotypeCaller produces 1,135 multi-allelic sites out of 7,433 total (15%). These are overwhelmingly **+1/-1 bp indels** (93% multi-indel) — classic homopolymer stutter from PCR/sequencing in repeat regions. Only 12% pass quality filters vs 9.3% for biallelic (similar quality profile).

Multi-allelic FORMAT fields like VAF are comma-separated strings (e.g., `0.64,0.083`), which breaks numeric filtering in Tabulator.js.

### Solution: `bcftools norm -m-` with `--old-rec-tag`

```bash
bcftools norm -m- --old-rec-tag ORIG_ALT --force input.vcf.gz -Oz -o split.vcf.gz
```

- Splits each multi-allelic site into separate biallelic rows
- `--old-rec-tag ORIG_ALT` preserves the original record as `INFO/ORIG_ALT=chr10|4920|G|GA,GAA|1` (format: `CHR|POS|REF|ALT|USED_ALT_IDX`)
- `--force` required because HaplotypeCaller PL fields have wrong cardinality for high-ploidy multi-allelic sites (known GATK issue)
- After splitting, all FORMAT fields (VAF, AD, DP, GQ) become scalar → numeric Tabulator filters work

### Caveats

1. **SnpEff ANN not split**: `bcftools norm -m-` does NOT split the ANN field — both split rows carry all annotations for all original ALTs. Options:
   - Re-annotate with SnpEff after splitting (cleanest)
   - Use `SnpSift extractFields` to filter ANN by allele
   - Accept duplicate annotations (acceptable for review — igvreports shows all anyway)

2. **Row count increases**: 7,433 → ~8,568 rows (+15%)

3. **ORIG_ALT as INFO column**: Add `--info-columns ORIG_ALT` to igvreports to show the original multi-allelic context in the table. Useful for identifying split records during review.

### Recommended pipeline order

```
bcftools norm -m- --old-rec-tag ORIG_ALT --force  # split multi-allelics
→ AWK (copy FILTER → VCF_FILTER)                  # preserve FILTER as INFO
→ bcftools +fill-tags -- -t FORMAT/VAF             # add per-sample VAF
→ create_report --template custom.html             # generate report
→ python3 embed_vcf.py                             # inject base64 VCF for download
```

## FILTER Column in igvreports

### Problem
`--info-columns FILTER` produces an empty column. igvreports only reads `variant.info[h]` (INFO dict), not the fixed FILTER column (VCF column 7).

### Solution
Pre-process VCF with AWK to copy FILTER → `INFO/VCF_FILTER`, then use `--info-columns VCF_FILTER`:

```bash
bcftools view input.vcf.gz \
    | awk 'BEGIN{OFS="\t"}
        /^##/{print; next}
        /^#CHROM/{
            print "##INFO=<ID=VCF_FILTER,Number=1,Type=String,Description=\"Original VCF FILTER value\">"
            print; next
        }
        {
            filt=$7
            gsub(/;/, ",", filt)   # semicolons conflict with INFO delimiter
            $8="VCF_FILTER=" filt ";" $8
            print
        }' \
    | bgzip > prepared.vcf.gz
```

**Note**: FILTER values like `MQ_filter;SOR_filter` contain semicolons that are INFO field delimiters. The AWK replaces them with commas.

## GFF3 Gene Track

The GFF3 from snpeff_cache (`draft_ref52.gff3`, 14 MB) works as an IGV track via `--tracks genes.sorted.gff3.gz`. It must be sorted, bgzipped, and tabix-indexed first.

The GFF3 contains overlapping feature types (gene + mRNA + CDS) for the same loci, which renders as duplicate tracks in the IGV view. For yeast (minimal splicing), this is cosmetic — both tracks show the same gene boundaries.

## Known Limitation: 3-Frame Amino Acid Translation

### Problem
The igvteam example ([example_vcf_tabulator.html](https://igvteam.github.io/igv-reports/examples/example_vcf_tabulator.html)) shows 3-frame amino acid translation below the reference sequence. This uses `--genome hg38`, which triggers igv.js's built-in genome configuration with `showTranslation: true`.

### Status: NOT supported for custom genomes

When using `--fasta` (custom reference), igv-reports creates a minimal reference config with only `fastaURL` — no `showTranslation` flag. The igv.js viewer does not render amino acid translation.

**Attempted fix**: Monkey-patched `report.create_session_dict()` to inject `"showTranslation": true` into the reference config within session data URIs. The injection succeeded technically but the translation **did not render** in the browser.

**Root cause**: igv.js likely requires additional genome metadata (cytobands, chromosome aliases) or a different reference config structure to enable translation for custom genomes.

**Workaround**: The SnpEff ANN field already provides PROTEIN ALTERATION and DNA ALTERATION columns in the variant table, which covers the primary use case of identifying amino acid changes at variant positions.

## Demo Workflow: `generate_demo_reports.nf` (May 2026)

Streamlined workflow for I1 samples only, replacing the earlier `generate_all_reports.nf`.

### Key improvements over original workflow
- **igv-reports v1.16.0** (upgraded from v1.12.0)
- **Custom HTML templates** (`--template`) replacing `--tabulator` + `sed` post-processing
- **Multi-allelic splitting** (`bcftools norm -m- --old-rec-tag ORIG_ALT --force`)
- **Embedded column settings** in template (formatters, filter types) — `filter_config.yaml` no longer relied on at runtime
- **Embedded VCF download** — base64-encoded gzipped VCF injected into HTML for self-contained download
- **Filter export/import** — save and reload column filter configurations as JSON

### Custom template system (implemented)

igv-reports `--template custom.html` completely replaces the built-in template. Only **3 placeholders** are actually used (others documented upstream are not real):

| Placeholder | Data | Notes |
|---|---|---|
| `"@TABLE_JSON@"` | `{headers: [...], rows: [[...]]}` | Must be in double quotes |
| `"@SESSION_DICTIONARY@"` | Row ID → IGV session data URI mapping | Must be in double quotes |
| `"@FILTER_CONFIG@"` | filter_config.yaml as JSON (null with custom template) | Must be in double quotes |

**Important**: `@IGV_CONFIG@` is NOT a real placeholder — upstream code uses `sessionDictionary["0"]` directly for the initial IGV session. Placeholders must be wrapped in double quotes or they are not replaced.

**Additional custom placeholders** (injected by Python post-processing):
| Placeholder | Data |
|---|---|
| `@VCF_BASE64@` | Base64-encoded gzipped VCF for download button |
| `@VCF_FILENAME@` | Filename shown in download dialog |

### Two templates

| Template | File | Table:IGV Split | Use Case |
|----------|------|-----------------|----------|
| Cohort | `custom_template.html` | 7:3 (table-heavy) | All variants, no alignment tracks |
| Per-sample | `custom_template_sample.html` | 1:1 (equal) | Per-sample with CRAM pileups + GFF3 |

### Template features (both templates)
- **Sticky pagination footer** — always visible without scrolling
- **Resizable split panes** — drag handle between table and IGV panels
- **Tabulator.js v6.3.0** — virtual scrolling, pagination (10/25/50/100 per page)
- **Column filters** — text search, numeric range, all embedded in `columnSettings`
- **ANN column formatters** — `formatter: "html"` for line breaks; `annCondensedFormatter` for PROTEIN/DNA ALTERATION (strips empty entries, pairs with gene name)
- **Toolbar buttons** (color-blind safe palette):
  - Clear Filters (gray) — reset all column filters
  - Export Filters (orange) — save current filter config as JSON
  - Import Filters (orange) — load saved filter config from JSON
  - Export CSV (blue) — download filtered rows as CSV
  - Download VCF (purple) — download embedded VCF file
- **Row click → IGV navigation** — clicking a variant row loads that position in IGV

### `--filter-config` behavior with custom templates

The `--filter-config` YAML is only parsed into the `@FILTER_CONFIG@` placeholder when `--tabulator` (built-in template) is used. With `--template` (custom), `filterConfig` is always `null`. Column settings must be embedded directly in the template JavaScript.

The `filter_config.yaml` file is still passed to `create_report` for compatibility but has no runtime effect with custom templates.

### ✅ IMPLEMENTED: Cross-Linking Cohort ↔ Sample Reports (May 2026)

**Goal**: Click a sample's GT cell in the cohort table → open that sample's per-sample report at the corresponding variant position.

#### How it works

1. **Cohort template** (`custom_template.html`): `cellClick` event on sample columns (format: `SampleName:GT`, `SampleName:AD`, etc.)
   - Only fires when sample's GT is non-ref (≠ `0/0`, `./.`, `0|0`, `.|.`)
   - Strips patient prefix from column name to get sample filename
   - Opens `samples/{sampleName}_report.html?locus=CHROM:POSITION` in new tab
   - Uses `e.stopPropagation()` to prevent `rowClick` (IGV load) from also firing

2. **Sample template** (`custom_template_sample.html`): Reads `?locus=` URL parameter on load
   - Waits for `renderComplete` event (table fully rendered)
   - Searches all data for matching CHROM + POSITION (handles both string and numeric comparison)
   - Expands page size to show all rows (enables scrollable table)
   - Selects and scrolls to the target row using `scrollIntoView({ block: "center" })`
   - Loads the IGV session for that variant (alignment view)

#### Scroll behavior for locus navigation

When arriving via `?locus=` parameter, pagination is removed and the table becomes a scrollable list. The target row is scrolled with `scrollIntoView({ block: "center" })`:

- **Row near top**: Highlights in place (browser can't scroll higher)
- **Row in middle**: Scrolls to center of visible area
- **Row near bottom**: Scrolls as far as possible, shows surrounding context

This natural scrolling behavior works because Tabulator with `height: "100%"` uses virtual DOM rendering, handling 130+ rows efficiently.

#### Key constraint: igv-reports data embedding

igv-reports only embeds alignment data for variant positions present in the input VCF. This means:

| Scenario | Table row? | Alignment reads? | Link available? |
|----------|-----------|-----------------|----------------|
| Sample has variant (GT ≠ 0/0) | ✅ | ✅ | ✅ Yes |
| Sample is homref (GT = 0/0) | ❌ | ❌ | ❌ No link |
| Position not in sample VCF | ❌ | ❌ | ❌ No link |

#### Scalability

| Mutations per sample | Scroll performance | Notes |
|---------------------|-------------------|-------|
| ~130 (current) | ✅ Smooth | Tabulator virtual rendering |
| ~500-1,000 | ✅ Fine | Expected ALE range |
| ~5,000+ | ⚠️ Test needed | Virtual rendering should still handle it |

- **INFO columns**: ANN (auto-parsed → 7 sub-columns), VCF_FILTER, AC, AF, DP, QD, MQ
- **FORMAT columns**: GT, AD, DP, GQ, VAF

## Variant Review Strategy: Three-Tier Approach (May 2026)

### Design Principle: Progressive Complexity

Tiers are ordered by **barrier to entry** — the biologist starts with the simplest tool (open a file) and only moves to more complex tools when needed.

### Why Not igv-jupyter for Alignments?

igv-jupyter (the IGV.js Jupyter widget) serves BAM/CRAM files through Jupyter's kernel comm channel — Python `seek()`+`read()` calls relayed to the browser via 100ms polling. This creates problems with cloud-mounted filesystems:

- **GitHub igvteam/igv-notebook#26**: BAM files on mounted directories **time out after 30+ minutes** or produce 408 errors
- The maintainer (jrobinso) states the `path` property was "primarily added for Colab" — URL-based loading is preferred
- BAM/CRAM random-access patterns (many index seeks) hit FUSE latency hard
- **Seqera Fusion was designed for Nextflow's sequential I/O**, not IGV's random-access pattern
- igv-jupyter with VCFs (small, sequential reads) works fine — the problem is specific to large indexed alignment files

### Tier 1: igv-reports HTML — Zero-Code Variant Review

**Purpose**: Variant filtering, read pileup inspection, shareable reports
**Platform**: Any browser (standalone HTML files, no server needed)
**Barrier**: None — open a file, click around
**Programming required**: None

This is the **primary entry point** for biologists. Generated automatically by the Nextflow pipeline (`generate_demo_reports.nf`), the HTML reports are self-contained and require no installation, no server, no programming.

**User workflow**:
1. Open `index.html` in browser
2. Click cohort report → filter by GENE, IMPACT, VCF_FILTER
3. Click a variant row → see IGV pileup at that position
4. Click a sample's GT cell → opens that sample's report at the exact variant with reads
5. Export filtered variants as CSV for further analysis
6. Import/export filter configurations to share with colleagues

**Features** (documented in detail in "Demo Workflow" section above):
- Custom Tabulator.js template with virtual scrolling (handles 8,689+ variants)
- Per-column filtering (text search, dropdown, numeric range) with export/import
- CSV export of filtered rows + embedded VCF download
- Resizable table/IGV split with drag handle
- Cohort report (all variants, 7:3 split) + per-sample reports (with CRAM pileups, 1:1 split)
- Color-blind safe toolbar buttons
- Cross-linking: click sample GT cell in cohort → opens sample report at that variant

**Output structure**:
```
demo/
├── index.html                    # Navigation hub
├── cohort_report.html            # 8,689 variants, custom template (7:3 split)
└── samples/
    ├── A0-F0-I1-R1_report.html   # Per-sample: ~130-153 variants + CRAM pileups (1:1 split)
    └── ...
```

**Status**: **Done** — fully integrated into Nextflow pipeline

### Tier 2: Jupyter Studio — Programmatic VCF Analysis & Plots

**Purpose**: Cross-sample comparison, statistical analysis, publication-quality figures
**Platform**: Seqera Cloud Studios (Jupyter template + Conda augmentation)
**Barrier**: Basic Python — run pre-written cells, modify parameters
**Programming required**: Light (template notebook provided, user adjusts parameters)

**When to use** (instead of igv-reports):
- Comparing variants across multiple samples programmatically
- Generating publication-quality plots (VAF distributions, mutation spectra)
- Applying custom filters not available in the HTML toolbar
- Batch operations across all samples
- Statistical tests (Fisher's exact for gene enrichment, etc.)

**Conda packages needed**:
```yaml
- cyvcf2
- pysam
- pandas
- plotly
- seaborn
- matplotlib
- bcftools
- jupyterlab
```

**Analysis capabilities**:
- Load VCFs from `individual_from_joint/` and filtered outputs via `/workspace/data/<link_name>/`
- Cross-sample variant overlap and unique mutation identification
- VAF distribution histograms per sample/tool
- Mutation spectrum analysis (SNV types, ts/tv ratio)
- Gene-level mutation burden heatmaps
- Multi-tool concordance (HaplotypeCaller vs FreeBayes vs Mutect2)
- Interactive filtering with pandas (impact, AF thresholds, gene lists)

**Data access in Studios**:
- Seqera Studios mounts Azure Blob via Fusion at `/workspace/data/<link_name>/`
- VCF files appear as regular local paths — no URL setup needed
- VCFs are small enough that FUSE latency is not an issue

**Status**: Template notebook to be created

### Tier 3: Desktop IGV via Xpra Studio — Interactive Alignment Exploration

**Purpose**: Free-form genome browsing, multi-track visualization, ad-hoc investigation
**Platform**: Seqera Cloud Studios (Xpra template)
**Barrier**: Platform setup — launch Studio, configure tracks
**Programming required**: None (GUI application)

**When to use** (instead of igv-reports):
- Browsing regions not centered on known variants
- Comparing multiple samples side-by-side at the same locus
- Loading additional tracks (GFF3, BED, bigWig) interactively
- Investigating structural variants or copy number regions
- Exploratory analysis where you don't know what you're looking for

**Setup in Studios**:
- Use the **Xpra base template** (provides full Linux desktop environment)
- IGV desktop application loads BAM/CRAM files from Fusion mounts at `/workspace/data/<link_name>/`
- Seqera has demonstrated this working with 1000 Genomes BAMs — **proven approach**
- Random access performance is better than igv-jupyter because IGV desktop handles I/O natively (no kernel comm polling overhead)

**Data access**:
- Mount `aledata` blob container as a data link
- BAM/CRAM + index files accessible at `/workspace/data/aledata/...`
- Reference FASTA similarly mounted

**Status**: Documented, not yet set up
