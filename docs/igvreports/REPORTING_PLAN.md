# Reporting Improvements Plan

**Date**: 2026-05-26
**Scope**: Adapt Marko SV dashboard aesthetics + CNV matrix visualizations into the ALE reporting system

## Current State

### IGV Reports Dashboard (`docs/igvreports/demo/index.html`)
- Light theme only, basic CSS (hardcoded colors, no CSS variables)
- Tabulator tables, badge system for impact levels (HIGH/MOD/LOW)
- Generated by `generate_index.py` using Jinja2 template (`templates/index.html.j2`)
- MultiQC data integration (alignment stats table)

### Marko SV Dashboard (`docs/benchmarking/marko_sv/sv_comparison/report/index.html`)
- Polished dark/light theme with CSS custom properties (`--bg`, `--fg`, `--surface`, etc.)
- Badge system: pass/warn/fail/na with theme-aware colors
- Finding cards with colored left borders (warn/note/good/info)
- Responsive layout, `color-scheme` meta tag
- Tabulator with theme-aware overrides

### Gap
The IGV demo dashboard lacks: dark mode, CSS variable system, finding cards, consistent color semantics across themes.

## Plan

### Phase 1: Adopt Marko SV CSS variable system into IGV dashboard template

**File**: `docs/igvreports/templates/index.html.j2`

Changes:
- Replace hardcoded colors with CSS custom properties from Marko SV theme
- Add `[data-theme="dark"]` block with dark palette
- Add theme toggle button (JS, same pattern as Marko SV)
- Update Tabulator overrides to use `var(--surface)`, `var(--border)`, etc.
- Update `.badge-high`, `.badge-mod`, `.badge-low` to use theme-aware variables
- Keep layout and structure unchanged — cosmetic-only changes

**Deliverable**: `generate_index.py` → regenerate `demo/index.html` with new template, visually identical in light mode but gains dark mode support.

### Phase 2: Add CNV matrix section to dashboard

**Depends on**: Validation plan Step 2 (dual CN matrices from `.call.cns` / `.germline.call.cns`)

Changes to `generate_index.py`:
- Accept optional `--cnv-matrix` argument (CSV from CN matrix builder)
- Render chromosome-level CN heatmap table (samples × chromosomes, color-coded CN values)
- Use badge-style coloring: cn=2 neutral, cn<2 deletion (red), cn>2 gain (blue/green)
- Add as new section in dashboard below MultiQC alignment stats

**Template changes** (`index.html.j2`):
- New `{% if cnv_matrix %}` block with CN heatmap table
- CN color scale function in JS (maps CN → background color)

### Phase 2a: UI/UX Prototype — Mutation Overview Report

**Goal**: Quick prototype to demo CN + SV cohort tables to the team, validate layout and interaction before full pipeline integration.

**Approach**: Single self-contained HTML file (no build step), reads pilot CSVs inline via Jinja2 or embedded JSON. Focus on table presentation and interactivity, not data generation.

**Input data** (copied to `docs/igvreports/ottilie_4samples/`, 4-sample pilot — sufficient for UI prototyping; tier2 has 60+ samples; source: `docs/benchmarking/ottilie_xenobiotic_ale/04_validate/pilot_results/`):

| Section | File | Rows | What it shows |
|---------|------|------|---------------|
| CN heatmap (chr-level) | `cn_chr_summary_sensitive.csv` | 16 | Chromosome × sample grid, one CN per cell |
| CN heatmap (chr-level, stringent) | `cn_chr_summary_stringent.csv` | 16 | Same, CI-filtered — toggle to compare |
| CN regions (collapsed) | `cn_cohort_collapsed_sensitive.csv` | 22 | Genomic regions with CNV boundaries, position × sample |
| CN regions (collapsed, stringent) | `cn_cohort_collapsed_stringent.csv` | 22 | Same, CI-filtered |
| SV events (PASS) | `sv_cohort_matrix_union_pass.csv` | 105 | SV event × sample, caller attribution badges |
| SV events (all) | `sv_cohort_matrix_union.csv` | 426 | Full unfiltered — toggle to compare |

See `pilot_results/DATA_INDEX.md` for full column descriptions and source details.

**Prototype sections**:

1. **CN Chromosome Heatmap**
   - Grid: 16 rows (chromosomes I–XVI) × N sample columns
   - Cell color: cn=2 neutral (grey), cn<2 loss (red), cn>2 gain (blue), cn≥10 amplification (dark blue)
   - **Note**: CNVKit always uses diploid-scale CN (cn=2 = baseline) regardless of organism ploidy. For haploid yeast, cn=2 means "normal", cn=1 = loss, cn=3 = gain. See `docs/variant-calling/cnvkit/cnvkit_ploidy_cn_scale.md`.
   - Tabs with row counts: `CN Chromosome Sensitive #16` / `CN Chromosome Stringent #16` (highlight the 1 differing call: CBR110 chr VI)
   - Tooltip: log2, absolute_cn on hover

2. **CN Region Detail Table**
   - Tabulator table from collapsed matrix (22 rows)
   - Columns: chromosome, start, end, span (kb), then {sample}_diploid_cn
   - Color-coded CN cells (same scale as heatmap)
   - Tabs with row counts: `CN Regions Sensitive #22` / `CN Regions Stringent #22`
   - Filter: show only non-baseline regions (where any sample ≠ 2)

3. **SV Event Matrix**
   - Tabulator table from cohort matrix
   - Columns: chrom, pos, chrom2, end, svtype, svlen, then {sample} columns
   - Sample cells: badge-style (`Manta` green, `TIDDIT` blue, `Manta+TIDDIT` purple, `-` grey)
   - Tabs with row counts: `SV Cohort #426` / `SV High-Quality #105`
   - Filters: by svtype (DEL/DUP/INV/TRA), by shared vs private, by chromosome
   - Caller badge tooltip: show caller-specific FILTER status on hover

4. **Summary Cards** (top of page)
   - Total samples, total SV events, CN changes detected
   - Sensitive vs stringent agreement rate
   - SV PASS filter reduction (426 → 105)

**Tab naming convention**: Each data view tab shows the dataset name and row count, e.g. `SV Cohort #426`, `SV High-Quality #105`, `CN Regions Sensitive #22`. This matches the existing pattern in the IGV reports dashboard (e.g. "HaplotypeCaller Cohort Report").

**Styling**: Reuse Marko SV dashboard CSS variables (dark/light theme, badge system, finding cards).

**Deliverables**:
- `docs/igvreports/ottilie_4samples/mutation_overview.html` — self-contained prototype
- `docs/igvreports/ottilie_4samples/generate_prototype.py` — reads pilot CSVs, renders template

**Timeline**: After Phase 1 CSS migration, **before Phase 2** — team feedback on the prototype informs the full pipeline integration design.

### Phase 3: Reusable dashboard template extraction

Extract the shared CSS/JS (theme system, Tabulator config, badge definitions) into a standalone template or partial that both the IGV dashboard and Marko SV report can import. Reduces duplication if more dashboards are added.

**Options**:
- Jinja2 `{% include "shared_theme.css" %}` partial
- Standalone `dashboard_base.css` + `dashboard_base.js` files referenced by both templates

Lower priority — only worthwhile if a third dashboard is planned.
