## Multi-Allelic Site Splitting

### What Are Multi-Allelic Sites?

Multi-allelic sites are genomic positions where more than one alternate allele is observed relative to the reference.

**Example:**
```
Position: chr1:1000
REF: A
ALT: T,G    (two alternate alleles at same position)
```

### Why Split Multi-Allelic Sites?

**Pipeline Behavior:**
- FreeBayes germline filtering preserves multi-allelic sites by default
- Some downstream tools expect bi-allelic VCF format (one ALT per record)
- Splitting simplifies allele-specific filtering and annotation

### How to Split Multi-Allelic Sites

#### Using bcftools norm

**Basic splitting:**
```bash
bcftools norm -m- input.vcf.gz -O z -o output.split.vcf.gz
bcftools index -t output.split.vcf.gz
```

**What happens:**
- `-m-` splits multi-allelic sites into multiple records
- Each alternate allele becomes a separate VCF record
- All INFO/FORMAT fields are adjusted accordingly

#### Example Transformation

**Before splitting:**
```
AECK01000002  547636  .  AGTATAC  TGTGTAT,AGTGTAC  60  .  AO=12,5;RO=3  GT:AO:RO  0/1:12,5:3
```

**After splitting:**
```
AECK01000002  547636  .  AGTATAC  TGTGTAT  60  .  AO=12;RO=3  GT:AO:RO  0/1:12:3
AECK01000002  547636  .  AGTATAC  AGTGTAC  60  .  AO=5;RO=3   GT:AO:RO  0/1:5:3
```

### When to Split

✅ **Split when:**
- Using tools that don't support multi-allelic VCF (e.g., some ANNOVAR workflows)
- Performing allele-specific filtering (e.g., different AF thresholds per allele)
- Creating publication-ready variant tables (easier to interpret)

❌ **Don't split when:**
- Working with tools that handle multi-allelic sites correctly (e.g., SnpEff, VEP)
- Performing phasing analysis (splitting loses allelic relationships)
- Storage space is a concern (splitting increases file size)

### Advanced Splitting Options

**Split and left-align indels:**
```bash
bcftools norm -m- -f reference.fasta input.vcf.gz -O z -o output.split.norm.vcf.gz
```

**Split only SNPs (keep indels as-is):**
```bash
bcftools norm -m-snps input.vcf.gz -O z -o output.split_snps.vcf.gz
```

**Split and remove duplicates:**
```bash
bcftools norm -m- -d all input.vcf.gz -O z -o output.split.dedup.vcf.gz
```

## Extract PASS-Only Variants

Filter to keep only variants that passed all quality filters:

```bash
bcftools view -f PASS input.vcf.gz -O z -o output.pass.vcf.gz
bcftools index -t output.pass.vcf.gz
```

**Use case:** Joint germline calling produces filter-annotated VCFs where most variants are flagged. Extract PASS variants for high-confidence analysis.

## Sample-Specific Extraction

Extract variants for a specific sample from multi-sample VCF:

```bash
# List samples in VCF
bcftools query -l input.vcf.gz

# Extract single sample
bcftools view -s SAMPLE_NAME input.vcf.gz -O z -o sample.vcf.gz
bcftools index -t sample.vcf.gz
```

**Use case:** Joint calling produces combined VCF. Extract individual sample results for sample-specific analysis.

## Variant Type Filtering

**Extract only SNPs:**
```bash
bcftools view -v snps input.vcf.gz -O z -o snps_only.vcf.gz
```

**Extract only INDELs:**
```bash
bcftools view -v indels input.vcf.gz -O z -o indels_only.vcf.gz
```

**Extract SNPs and INDELs separately (combined):**
```bash
bcftools view -v snps,indels input.vcf.gz -O z -o snps_indels.vcf.gz
```

## Example Workflow: FreeBayes Post-Processing

**Scenario:** You want to analyze FreeBayes germline results with multi-allelic splitting and PASS-only filtering.

```bash
# Set paths
INPUT="output_all/variant_calling_filtered/freebayes/sample/sample.normal.vcf.gz"
OUTPUT_DIR="analysis/freebayes_processed"
mkdir -p $OUTPUT_DIR

# Step 1: Split multi-allelic sites
bcftools norm -m- -f reference.fasta $INPUT \\
    -O z -o $OUTPUT_DIR/sample.split.vcf.gz

# Step 2: Index
bcftools index -t $OUTPUT_DIR/sample.split.vcf.gz

# Step 3: Extract high-quality variants (optional custom filter)
bcftools view -i 'QUAL>=30 && INFO/DP>=15' \\
    $OUTPUT_DIR/sample.split.vcf.gz \\
    -O z -o $OUTPUT_DIR/sample.split.hq.vcf.gz

# Step 4: Index final output
bcftools index -t $OUTPUT_DIR/sample.split.hq.vcf.gz

# Step 5: Generate summary statistics
bcftools stats $OUTPUT_DIR/sample.split.hq.vcf.gz > $OUTPUT_DIR/sample.stats.txt
```

## Performance Considerations

**Multi-allelic splitting impact:**
- File size: +10-30% (depends on multi-allelic frequency)
- Processing time: ~30-60 seconds per 10K variants
- Memory: Minimal (streaming operation)

**Optimization tips:**
```bash
# Use threads for compression
bcftools norm -m- input.vcf.gz --threads 4 -O z -o output.vcf.gz

# Combine multiple operations in one pass
bcftools norm -m- input.vcf.gz | bcftools view -f PASS -O z -o output.vcf.gz
```
