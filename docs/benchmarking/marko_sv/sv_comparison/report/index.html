Key Findings

Mobile element insertion (MOB) calls are breseq-unique. 3 IS-element mobilizations (2×IS2, 1×IS5) detected only by breseq. This is expected: standard SV callers cannot resolve insertions of repeat elements already present elsewhere in the genome. breseq uses assembly-based junction detection.

In prokaryotes, MOBs are predominantly insertion sequence (IS) element insertions, for which breseq is the established tool.

In eukaryotic microbes such as S. cerevisiae, MOBs are predominantly insertions of long terminal repeat (LTR) retrotransposons (the Ty1–Ty5 families in yeast), detectable by RelocaTE2, TEMP, TEMP2, and TEBreak (Chen et al. 2023, Mobile DNA), but reliable calling depends on a high-quality reference genome paired with comprehensive, consistent mobile element annotation, including both coordinate records on the chromosome and a curated consensus sequence library. The latter set is not currently integrated into yAMP v1.0.0.

Filter metrics explained (QD, DP, SOR)

GATK VariantFiltration populates the FILTER column with PASS or named filter tags but does not remove any variants. This is a soft filter fallback used when VQSR cannot run (no known variant resources for custom genomes).

Column Metric Filter Threshold Interpretation
QD Quality by Depth QD < 2.0 → QD_filter QUAL score / total depth. Low QD = weak evidence per read. Higher is better.
DP Read Depth — (no filter) Total reads at this position (INFO/DP, cohort-level). Shown for context only.
SOR Strand Odds Ratio SOR > 3.0 → SOR_filter Strand bias test. SOR > 3.0 = variant seen disproportionately on one strand (possible artifact). Lower is better.
HC Filter FILTER column Combined result PASS = passes all filters. Otherwise shows which filter(s) flagged the variant (e.g. QD_filter, SOR_filter, MQ_filter).

Other soft filters applied (not shown as columns): FS > 60.0 (FS_filter), MQ < 40.0 (MQ_filter), MQRankSum < -12.5, ReadPosRankSum < -8.0, QUAL < 30.0. INDEL thresholds are more lenient (FS > 200, SOR > 10).

Thresholds follow GATK best practices for human data. See conf/modules/joint_germline.config for full configuration.

SNP/InDel report (HaplotypeCaller)

The per-sample IGV report SRR6281661_report.html is generated from the snpEff-annotated HaplotypeCaller VCF (SRR6281661.haplotypecaller.from_joint_calling_snpEff.ann.vcf.gz) using igv-reports.

Processing steps (see generate_igvreport.sh):

  1. Multi-allelic split — bcftools norm -m- splits multi-allelic sites so each alt allele has its own row.
  2. FILTER promotion — The original FILTER column value (e.g. PASS, SOR_filter) is copied into an INFO tag VCF_FILTER so it appears as a searchable column in the report table.
  3. VAF annotation — bcftools +fill-tags adds a FORMAT/VAF field for allele-fraction display.
  4. Report creation — create_report renders each variant with ±500 bp flanking, the CRAM alignment track, and GFF3 gene annotations.
    create_report hc_prepared.vcf.gz --fasta ref.fasta --tracks genes.sorted.gff3.gz sample.md.cram --template custom_template_sample.html --filter-config filter_config.yaml --info-columns ANN VCF_FILTER ORIG_ALT AC AF DP QD MQ --sample-columns GT AD DP GQ VAF --flanking 500 --title "SRR6281661 - HaplotypeCaller SNP/InDel (E. coli K-12)" --output SRR6281661_report.html
  5. VCF embedding — The prepared VCF is base64-encoded into the HTML for self-contained download.

The report contains 76 variants (all from joint gVCF calling, soft-filtered) and allows interactive sorting, filtering, and IGV-style pileup inspection per variant.
